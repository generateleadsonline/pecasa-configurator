# Private quote capture and design pack

`POST /api/quote` accepts a validated design and contact details. The indicative price is calculated server-side only from the verified Pecasa London table; unsupported footprints/structures return `total: null`, `totalLabel: "Bespoke quote"`. Selected extras have no invented allowance. Response is returned only after a strongly consistent Netlify Blobs write/readback confirms the accepted enquiry.

Payload: `{ lead: { name, email, postcode, phone?, timeline?, notes?, marketing, website?: "" }, design, image?: "data:image/jpeg;base64,...", idempotencyKey, shareUrl? }`. POST requires a same-origin `Origin` header. The server reconstructs the privacy-safe share URL from the validated design; submitted `shareUrl` is never trusted. Design height is fixed to the 2.5 m concept value. Dimensions respect researched source limits in 0.1 m increments.

The response contains `{ reference, quote, token, pdfUrl, design, shareUrl }`. The token is a cryptographically random 256-bit bearer credential and is hashed in storage paths. `GET /api/quote?token=...` restores an accepted design without contact details. An accepted update uses `{ token, design, image?, idempotencyKey, shareUrl? }`, retaining the previously saved contact. Each saved version gets an immutable revision; its issued PDF URL keeps the same accepted specification even after further edits.

`GET /api/design-pack?token=...&revision=...` checks durable acceptance and ownership before generating four useful A4 pages on the server. It uses the captured JPEG, or authentic Pecasa project photography as fallback, an externally dimensioned indicative plan, all selected specifications, standard construction, honest investment scope, company contacts and a QR/link to reopen the exact design. Assets and Manrope fonts are embedded locally; no PDF request contacts a third-party service. The accepted link expires after 90 days. Responses are private/no-store and use no-referrer. Blobs records remain private; storage lifecycle/deletion should be configured to match the approved retention policy.

Lead destination: **private Netlify Blobs only** (`pecasa-private-quotes-v1` in production; isolated context stores elsewhere). No email, CRM or webhook has been connected, and no automatic external messages are sent. The operator can access accepted private records through the site's Netlify Blobs administration. Connect an approved CRM/inbox destination separately before making promises about team follow-up or emailed packs.

Distributed Netlify rate limits and local burst limits apply. Input/schema/contact validation, honeypot, body/JPEG size limits and generic non-PII diagnostics are implemented. Tokens should never be placed in analytics, share links or logs.

Verified pricing source: https://www.pecasa.co.uk/garden-rooms-london/ checked 11 October 2026. Published 3–8 m widths and 2.8/3/3.5/4/5 m depths only. Homepage and table disagree at the smallest footprint; this is disclosed. Styling and selected extras remain a quotation requirement.

Run `node --test tests/backend.test.mjs`. Once the real preview JPEG is available, run `node tests/check-scene-capture.mjs /absolute/path/scene.jpg` to validate capture acceptance and its actual embedding in the protected PDF. Tests verify pricing and source, real gate behavior, durable write/readback failures, idempotent retries, updates, immutable revisions, expiry, input/origin/body validation, JPEG limits, L-shape geometry consistency, fixed-style roof/open-structure compatibility, post-persistence retry recovery and server PDF creation. Render/visual QA covers default and all-option/long-name four-page samples; actual scene capture must also be checked after live integration.
